# Monash resources for an introductory AI EEG honours project

**As of and last checked: 26 October 2026 (Australia/Sydney).** Purpose: concise, factual input to a **12-slide introductory honours kickoff**, centred on eight strong opportunities. This is institutional resource research, not confirmation of this student's enrolment, eligibility, supervision, dataset permission, funding or booking. No people were contacted, applications submitted, accounts inspected or jobs run.

**Evidence convention:** Every supporting link below is a direct official institutional URL, checked on **2026-10-26**. “Full text” means the page body was retrieved; “indexed text” means official page content was readable in search results but subsequent live retrieval failed with HTTP 403 or timeout. Indexed evidence establishes the public listing, not present equipment operability or a current price quote. Publisher dates, where available, are distinguished from the check date. Recommendations and proposed actions are explicitly identified as such.

## 1. What compute is currently offered, and what access could an honours student seek?

### Takeaway

**Opportunity 1 — supervisor-backed M3 computing, with MAVERIC as a conditional escalation route.** M3 remains Monash's primary HPC service; MonARCH has closed; MAVERIC has actually launched. The practical starting route is an approved supervisor-led M3 project, subject to suitability of the data and workload. [M3 overview](https://docs.erc.monash.edu/Compute/HPC/M3/) · [MonARCH closure](https://docs.erc.monash.edu/Compute/HPC/MonARCH/) · [MAVERIC launch](https://www.monash.edu/news/articles/maveric-launched-to-accelerate-the-next-generation-of-australian-research) — checked 2026-10-26.

### Cited Findings

- **M3 status and use:** Current documentation calls M3 “formerly known as MASSIVE”; it describes CPUs, NVIDIA GPUs and parallel processing. The overview was updated **2 October 2026**, and warns of high GPU demand and cancellation of jobs that reserve but idle GPUs. This supports availability as a published service, not immediate GPU capacity. [M3 overview — full text](https://docs.erc.monash.edu/Compute/HPC/M3/) — checked 2026-10-26.
- **Actual account and membership route:** First sign into the eResearch Resource Allocation System to activate an identity; the project leader/CI then adds the person to an existing project with an M3 service. Users cannot independently request membership of an existing project; membership must be granted by its leader. [Create an M3 account](https://docs.erc.monash.edu/Compute/HPC/M3/GettingStarted/CreateM3Account/) · [Join an existing project](https://docs.erc.monash.edu/Compute/HPC/M3/GettingStarted/JoinExistingM3Project/) — full text; checked 2026-10-26.
- **Who leads; what is free:** The new-project guide says only Monash staff can apply for and lead standard M3 projects. It describes free access **for users who secure an allocation** through a partner/affiliate/merit route or integrated instrument. Its PEACH exception is for PhD/HDR students, not an explicit honours entitlement. [Create a new M3 project — full text, updated 17 September 2026](https://docs.erc.monash.edu/Compute/HPC/M3/GettingStarted/CreateM3Project/) — checked 2026-10-26.
- **Sensitive-data constraint:** M3's terms explicitly state it is **not certified to run sensitive data**. They direct users to classification guidance and identify SeRP and MAVERIC as possible sensitive-data services. Accounts are individual; credentials must not be shared. Compute jobs belong on compute nodes, with only light work on login nodes. [M3 terms — full text, updated 17 September 2026](https://docs.erc.monash.edu/Compute/HPC/M3/TermsOfUse/) — checked 2026-10-26.
- **MonARCH is retired:** The explicit final notice says it **closed on 1 September 2025**, and directs users to apply to M3; project/data migration was not automatic. PEACH is CPU-only, without GPU access. Older descriptive hardware sections remain on that same page and must not be mistaken for a live alternative. [MonARCH closure notice — full text](https://docs.erc.monash.edu/Compute/HPC/MonARCH/) — checked 2026-10-26.
- **MAVERIC is operational, not just proposed:** Monash's **5 June 2026** announcement states that MAVERIC officially launched and already had research projects underway. It describes a Trusted Research Environment for authorised analysis of sensitive data under enforceable controls. [MAVERIC launch — official indexed text; subsequent full-page fetch timed out](https://www.monash.edu/news/articles/maveric-launched-to-accelerate-the-next-generation-of-australian-research) — checked 2026-10-26.
- **MAVERIC workload implications:** The current compute guide lists large-memory/distributed AI training, sensitive-data support, ARM CPUs, Linux and container-only operation. It still calls M3 the primary HPC cluster; the two are presented alongside one another. Nectar requires users to administer their VMs; DUG incurs direct financial costs. [Choosing the right compute platform — full text, updated 10 September 2026](https://docs.erc.monash.edu/Compute/ChoosingCompute/) — checked 2026-10-26.

### Inferences

Seek membership of an existing approved M3 project where suitable, or have an eligible staff CI request a project. This is a proposed route, not evidence that the student has access. #### Opportunity 3 — storage, governance and controlled analysis

- **Active data:** RDS **Market** provides disk/network storage with group or machine access controls. - **Retention:** RDS **Vault** combines disk cache and tape, supports Public/Restricted classifications, and is intended for infrequently accessed data. [Research Data hub — full text](https://www.monash.edu/research/infrastructure/research-data) · [DMP+ — official indexed text](https://www.monash.edu/research/infrastructure/research-data/data-management-planning) — checked 2026-10-26.

It supports research outputs including datasets; publication must account for privacy, confidentiality, copyright and other constraints. Mediated health-data sharing requires formal applications/agreements and final custodian approval. [Publish data — official indexed text](https://www.monash.edu/library/researchers/working-with-research-data/publish-data) — checked 2026-10-26.

#### Recommended initial scope and decision sequence

1. **Proposed first decision:** Choose either existing EEG classification/representation learning or a tightly scoped EEG-to-fMRI analysis using an already authorised paired dataset. If paired data and a domain supervisor are not established, keep EEG–fMRI as context or a later extension; MBI hardware availability does not solve the dataset question. [IT EEG lead](https://www.supervisorconnect.it.monash.edu/index.php/projects/research/learning-massive-amounts-eeg-data) · [MBI access gates](https://www.monash.edu/researchinfrastructure/mbi/forms-and-policies) — checked 2026-10-26.
2. **Proposed minimum research result:** One simple feature-based baseline, one modest neural/representation model, a preprocessing specification, subject-separated train/validation/test evaluation, and one targeted robustness or ablation question. This is an introductory scope recommendation, not a promised result or prescribed Monash assessment format; cross-subject variation is the motivation in the IT listing. [EEG project rationale](https://www.supervisorconnect.it.monash.edu/index.php/projects/research/learning-massive-amounts-eeg-data) — checked 2026-10-26.
