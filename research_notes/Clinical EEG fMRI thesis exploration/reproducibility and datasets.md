# Practical reproducibility and external-data options for the M3 study

Audit checkpoint: **21 October 2026, Australia/Sydney**. Research stopped at the coordinator's requested boundary. This is a source/manifest audit, not a model reproduction or payload-level QC. The supplied feasibility report and its four supporting notes were the starting context. Existing project context identifies **VU and ds006040 as staged development data**; neither is an untouched final validation set. No M3 connection, job submission, bulk EEG/fMRI download, source-code edit, commit or push was performed in this audit. Downloads were confined to this notes directory: public code for inspection, papers, metadata/markers, small pilot tables/labels, and bounded NIfTI/eye-file header reads.

## 1. Which official neural alternatives can actually be implemented now?

### Takeaway

**Implement UnEBOLT first if an official alternative with a documented tensor interface is wanted; implement MARBLE next if the smaller architecture is the scientific comparison. Neither has a verified public task-trained checkpoint in the inspected official release. UniEFS remains a paper-level option pending an official code/weight release.** Do not confuse a LaBraM initialization or the original NeuroBOLT weights with weights for these newer models. [UnEBOLT README](https://github.com/neurdylab/UnEBOLT/blob/09a382897b85820854ddd4e47a1f851fa43d32d9/README.md), [MARBLE README](https://github.com/emeelkaa/marble/blob/28ae2ab16585f7a0cd57fcc961952661cce3e1d6/README.md), [UniEFS project](https://soupeeli.github.io/UniEFS/).

Immediately useful code facts:

- **UnEBOLT can bypass download/segmentation entirely with the prepared tensor pickle.** This avoids its default Hugging Face dataset download path. The code explicitly supports `--pretrained_weights ''` for training from scratch; the default LaBraM checkpoint initializes the encoder, not an EEG-to-BOLD readout. [Weight initialization](https://github.com/neurdylab/UnEBOLT/blob/09a382897b85820854ddd4e47a1f851fa43d32d9/main.py#L242), [tensor loader](https://github.com/neurdylab/UnEBOLT/blob/09a382897b85820854ddd4e47a1f851fa43d32d9/dataset_maker/get_datasets.py#L152).
- **Units and channels need an explicit adapter.** Both inspected engines divide EEG by 100; the documented pipeline supplies microvolts. MNE data in volts must be converted deliberately. The UnEBOLT montage is named and ordered in `main.py`; changing only a channel-count argument does not establish matching spatial identities. Its default sync name is `R149`, which is not the external datasets' verified marker name. [UnEBOLT engine](https://github.com/neurdylab/UnEBOLT/blob/09a382897b85820854ddd4e47a1f851fa43d32d9/engine.py), [configuration/montage](https://github.com/neurdylab/UnEBOLT/blob/09a382897b85820854ddd4e47a1f851fa43d32d9/main.py), [MARBLE engine](https://github.com/emeelkaa/marble/blob/28ae2ab16585f7a0cd57fcc961952661cce3e1d6/engine.py#L34).
- **MARBLE's VU evaluation assumes five validation and six test scans through batch sizes.** A different cohort must retain actual run boundaries rather than inherit that batching. Its `--eval` example is not evidence of downloadable trained weights; an explicit trained checkpoint is needed. [Evaluation batching](https://github.com/emeelkaa/marble/blob/28ae2ab16585f7a0cd57fcc961952661cce3e1d6/main.py#L189), [resume/evaluation code](https://github.com/emeelkaa/marble/blob/28ae2ab16585f7a0cd57fcc961952661cce3e1d6/main.py#L257).
- The original NeuroBOLT Hugging Face model repository lists seven approximately 96 MB regional/global checkpoints. Those are an available historical comparator, **not newer-model checkpoints**. No additional checkpoint-license grant was established by this audit. [Actual model file manifest](https://huggingface.co/api/models/ssssssup/NeuroBOLT/tree/main?recursive=true&limit=100).

### Inferences

1. Rank **UnEBOLT → MARBLE → UniEFS** for immediate implementation feasibility. MARBLE is the more compact published architecture, but its CUDA extensions add environment work. Train the first two on development people and preserve an external test before tuning.
2. Keep tuned ridge/shared spectral-lag models as matched controls. A new architecture on the same development data is a different contribution from a frozen new-site result. Use identical target definitions and available channel information.
3. A full UniEFS reproduction would additionally require the decoder pretraining/adaptation, prompts and software release. A simpler decoder-pretraining experiment can be proposed, but should not be called an official UniEFS reproduction.

### Gaps

- No author-trained UnEBOLT, MARBLE or UniEFS checkpoint was verified. Do not infer absence everywhere from an empty release list or unsuccessful search.
- No installed-environment or runtime smoke test was run. Parameter counts are paper reports, not local measurements. Licensing statements above describe the inspected files; checkpoint-specific permissions and dependency redistribution terms remain to be checked for an actual redistribution.
- UniEFS's handling of an entirely new dataset token and a prospective, causal replacement for epoch-level vigilance prompts remain implementation questions.

### Inferences

- NATVIEW gives a useful new-site BOLD/physiology pilot with relatively little acquisition engineering. Pupil area, blinks, eye closure and behavioural responsiveness are different endpoints. Treat missing pupil samples as missing until QC distinguishes tracking failure, blinks and sustained eye closure; use interpolation flags.
- ds003768 offers the clearest verified **behavioural** wakefulness signal here. Press presence is independent of EEG features; press absence is not a definitive sleep diagnosis. Its eye recording corroborates behaviour but repeats the button information in XDAT, so those two encodings are not independent replications.
- MULTI-CLARID is a strong physiology-control extension, not an independently labelled sleep test. Corrected EEG and required BOLD preprocessing make it actionable, not unusable.
- Keep all visits/runs of each person together. Do not sum these sources into a verified unique-person or independent-site sample size: cross-release identity mappings were not supplied.

### Gaps

- Listed modality intersections are not verified synchronized, usable hours. EEG payload integrity, eye coverage, residual artifacts and motion exclusions need the pilot.
- Latest ds003768 processed MRI is a **verified manifest resource with unresolved processing provenance**, not a verified ready-to-use target. Its 2.0/2.1-s discrepancy must not be silently repaired or interpreted as established resampling. Respiration/capnography were not verified in this release.
- NIH physiology format/content and timing of the protocol's random awakenings remain unresolved. Expert PSG scores can support sleep-state analyses but do not satisfy an independent non-EEG arousal-label claim.
