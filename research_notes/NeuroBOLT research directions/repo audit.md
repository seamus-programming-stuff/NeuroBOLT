# NeuroBOLT repository audit

## 1. What the implementation does and where it can mislead

### What is implemented

- `dataset_maker/get_datasets.py::prepare_onesub_dataloader` resamples VU EEG to 200 Hz, selects a single named DiFuMo target, low-pass filters the target below 0.15 Hz, applies per-scan demeaned 95th-percentile absolute normalization, pairs each scanner event with one fMRI frame, and splits the sequence 80:10:10 with ten TRs (about 21 seconds) skipped at each boundary. Each input is a 16-second window ending just before the frame (the 16 s epoch is cropped to 3,200 samples). See `dataset_maker/get_datasets.py:17-30,56-130`, `dataset_maker/preproc.py:5-32,35-108`.
- `prepare_full_dataloader` loads the `fold1` workbook split, concatenates samples from scans marked train/validation/test, resamples EEG, applies a 0.5-Hz high-pass to EEG, low-passes and normalizes each scan’s fMRI targets, then returns one flat dataset per split. The split sheet is the only mechanism for keeping both scans from a participant together; the loader does not validate subject separation, duplicate assignments, missing assignments, or expected scan counts. See `dataset_maker/get_datasets.py:133-259` and `README.md`'s requirement that scans from a subject stay in the same set.
- `models/model.py::NeuroBOLTransformer` combines a pretrained-LaBraM-style spatiotemporal path (26 channels × 16 one-second patches plus a CLS token) with `MSSEncoder`; it mean-pools both embeddings, adds them, applies GELU, and predicts `num_roi` values. `MSSEncoder` computes non-overlapping magnitude STFT windows at 0.5, 1, 2 and 4 seconds, projects each scale to the same temporal shape, sums scale embeddings with equal fixed weight, adds channel tokens, runs a four-layer/eight-head linear attention transformer and mean-pools. See `models/model.py:264-406`, `models/model_multiscale.py:94-197`.
- Training uses MSE, AdamW, cosine schedules, per-epoch validation, and a fixed seed argument. The model can emit multiple outputs (`--nb_roi`), but the CLI accepts `--labels_roi` as one string and both dataset loaders select a single ROI; there is no ready-to-use multi-ROI target path. See `main.py:43-214,240-258,517-535`, `dataset_maker/get_datasets.py:80-88,198-207`.

### Highest-priority correctness and paper-parity findings

1. **The current cross-subject reproduction path is not the paper’s primary EEG filtering setting.** `prepare_full_dataloader` always executes `eeg_raw.filter(l_freq=0.5, h_freq=None)` (`dataset_maker/get_datasets.py:195`). NeuroBOLT says its primary setting applies no additional EEG high- or low-pass filter; 0.5-Hz high-pass was a sensitivity check and was not retained because performance was close. The current M3 script uses `--train_test_mode full_test`, so its seven cross-subject runs use the sensitivity variant. Keep the active results as that variant; after they finish, run an explicitly named unfiltered counterpart for paper parity. [NeuroBOLT Appendix D](https://arxiv.org/html/2410.05341)
2. **AdamW betas differ from the paper.** Table 5 reports β=(0.9, 0.99). `main.py` leaves `--opt_betas` unset by default, and `optim_factory.py::create_optimizer` passes betas only if that argument is supplied; PyTorch AdamW therefore keeps its documented default β=(0.9, 0.999). The current `scripts/reproduce_rest_m3.sbatch` does not pass `--opt_betas`. Add `--opt_betas 0.9 0.99` only to a future controlled reproduction run; do not relabel current outputs as exact paper settings. The M3 script does correctly set 30 epochs, batch sizes 16/64, seed, and 5 warmup epochs; the general CLI default is only 20 epochs. See `main.py:45-46,85-91,101-113`, `optim_factory.py::create_optimizer`, `scripts/reproduce_rest_m3.sbatch:60-77`; [NeuroBOLT Appendix E](https://arxiv.org/html/2410.05341); [PyTorch AdamW defaults](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW).
3. **Cross-subject test metrics are not preserved per held-out scan.** The loader flattens all test scans (`dataset_maker/get_datasets.py:185-258`). `main.py` then sets test batch size to `int(len(dataset_test)/6)` (`main.py:365-395`), which creates approximately six chunks but does not preserve scan boundaries. In `engine.py::evaluate`, when the first chunk has at least 200 examples, predictions remain a list and `utils.get_metrics` averages correlation across those chunks (`engine.py:163-219`, `utils.py:1007-1048`); it neither knows each chunk’s source scan nor returns the six scan-level values/SD. The paper reports inter-subject results as mean ± SD across held-out scans. `collect_reproduction_results.py` treats the entire inter-subject run as `expected_n=1`, so its cross-subject SD is blank. This can prevent an exact reproduction of the paper’s inter-subject table even if mean R is close. Preserve a scan ID for each target and aggregate per scan; report the six scan scores and their mean/SD. [NeuroBOLT Table 1 and held-out scan description](https://arxiv.org/html/2410.05341)
4. **Test scores are computed every epoch and gate checkpoint saving.** `main.py` evaluates validation and test on every epoch, then saves the validation-MSE-best checkpoint only if `test_corr > 0` (`main.py:575-617`). The separate M3 collector picks the row with minimum `val_mse` and reads that epoch’s test scores (`scripts/collect_reproduction_results.py:27-41`), which is the right selection target; however, test visibility and save gating invite accidental test-driven decisions. A safer evaluator writes validation metrics during model selection, freezes the selected epoch/checkpoint, then runs test once. This is a reporting/evaluation fix, not a claim that the test score altered gradient updates.
5. **Synchronization is assumed, not checked.** `epoching_seq2one` indexes the fMRI matrix with MNE’s retained event ordinals (`dataset_maker/preproc.py:72-106`) and defaults to no discarded initial frames (`dropfmriframes=0`). It assumes one `R149` event per fMRI volume and matching first-frame offsets. Add assertions/logs for event count versus fMRI frames, monotonic/TR-like event spacing, dropped frame count, and exact selected indices. That is a low-risk data-integrity improvement; it can catch frame shifts that would corrupt all learned correspondences.
6. **Whole-scan operations complicate a strict held-out forecast interpretation.** Target demeaning/95th-percentile scaling is computed over the entire scan before the temporal split (`get_datasets.py:90-95,208-218`; `preproc.py:18-23`). `scipy.signal.filtfilt` is applied before the intra-scan split (`get_datasets.py:92,212`); SciPy documents that it filters forward and backward to achieve zero phase, so a filtered target near a split boundary can depend on observations on both sides. These choices align with the paper’s reported per-scan normalization/filtering recipe, so changing them breaks strict reproduction; they are potential transductive/temporal-context leakage under a forecasting claim. Report a separate strict-holdout preprocessing variant using train-only target scaling and an explicitly justified causal or partition-isolated filter, while retaining a paper-faithful result for comparison. Avoid presenting the strict variant as a direct reproduction. [SciPy `filtfilt`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.filtfilt.html)
7. **The epoch code applies whole-window EEG baseline correction not described in the paper’s stated recipe.** `mne.Epochs(..., baseline=(None,None))` removes each channel’s mean over the complete 16-second epoch (`preproc.py:95-98`); MNE documents `(None,None)` as using the whole epoch and subtracting that mean from each epoch/channel. The paper describes resampling and division by 100 and says no additional low/high-pass filter for its primary setting. This can suppress slow EEG offsets/features, which are potentially informative for BOLD; test `baseline=None` versus existing behavior with all other settings fixed. It is a mismatch in documented preprocessing, but unreported upstream preprocessing details mean its effect cannot be inferred from source alone. [NeuroBOLT Appendix D](https://arxiv.org/html/2410.05341); [MNE baseline correction](https://mne.tools/stable/generated/mne.Epochs.html)
8. **The split loader trusts the workbook.** The paper explicitly keeps multiple scans of one person in one split; the code comments/docstring explain that expectation but do not enforce it. Add a validation-only check that derives participant IDs from scan names and fails on any participant present in more than one split, plus checks that each row has exactly one assignment. Verify the actual `fold1` sheet before making any subject-generalization claim.
9. **Lower-priority architecture/documentation discrepancy:** NeuroBOLT Appendix E describes the spectral sequence as `32 × 26 + 1 CLS` tokens; current `MSSEncoder.forward` concatenates only the channel-time tokens and has no spectral CLS token before transformer pooling (`model_multiscale.py:153-197`). This is small compared with evaluation and preprocessing fidelity, but it is a direct code-paper difference worth documenting or ablation-testing if the exact block implementation is being reproduced.

### Cutting-edge directions, with scope caveats

- **Unified regional decoders and FC supervision (best fit to this code).** UnEBOLT, from the NeuroBOLT author group, identifies separate per-region fits as a scaling limit and studies a single adaptive multi-region model that also estimates functional connectivity. The repo’s single-output loader and M3 array are currently ROI specialists, so the highest-value extension is multi-target loading plus scan-level FC evaluation, not replacing the current baseline before it is reproduced. MARBLE independently explores ROI-conditioned cross-attention with a Mamba–Transformer encoder and reports parameter/memory efficiency on the NeuroBOLT dataset family. These 2026 papers provide timely, directly relevant architectures; their gains are not guaranteed on this exact split. [UnEBOLT, MIDL 2026](https://proceedings.mlr.press/v315/li26g.html); [MARBLE, MICCAI 2026](https://papers.miccai.org/miccai-2026/0612-Paper4437.html)
- **State-space sequence modeling.** Brain-Mamba shows a selective state-space approach for multivariate brain time series and multi-region structure, while MARBLE applies a Mamba–Transformer hybrid to EEG-to-fMRI. This is a principled alternative to the current quadratic temporal encoder, but the 16-s inputs are not especially long; test it for parameter/latency/robustness and scan-level prediction, not on an assumed asymptotic speed benefit. [Brain-Mamba, CHIL 2024](https://proceedings.mlr.press/v248/behrouz24a.html); [MARBLE](https://papers.miccai.org/miccai-2026/0612-Paper4437.html)
- **More transferable EEG encoders.** REVE is a 2025 large-scale EEG foundation model designed for varied electrode layouts/lengths and pretrained across many datasets. It is relevant if the project grows toward cross-site or variable-cap EEG, but its reported tasks are general EEG decoding, not simultaneous EEG→BOLD regression. First test frozen features or a small adapter with the current paired data; do not infer BOLD utility from EEG benchmarks alone. [REVE](https://arxiv.org/abs/2510.21585)
- **Condition-aligned probabilistic translation.** CATD proposes condition-aligned latent representations and temporal diffusion for EEG-to-fMRI generation/temporal detail. It is a preprint, so treat it as an exploratory probabilistic/super-resolution direction rather than established evidence; it becomes more interesting after deterministic, scan-aware baselines and an uncertainty metric are in place. [CATD preprint](https://arxiv.org/abs/2408.00777)

## 3. Missing capabilities and best first three M3 experiments

### What blocks a full and well-audited reproduction

- **No reference baseline implementations in the training path.** The paper compares several encoders/translation models, but `main.py::get_models` creates only `neurobolt_default` and `models/` contains only the NeuroBOLT implementation. Reproducing NeuroBOLT’s own rows is possible; reproducing comparative Tables 1/2 requires porting or independently implementing baseline models and documenting their adaptations. [NeuroBOLT baseline list](https://arxiv.org/html/2410.05341)
- **Inter-subject uncertainty/reporting is incomplete.** The scan-level labels are discarded by the flat concatenation and M3 collector; thus the six test-scan SD cannot be emitted faithfully. Retain participant, scan, frame and split IDs as sidecar metadata.
- **No task-condition workflow in the checked-in M3 runner.** `scripts/reproduce_rest_m3.sbatch` explicitly covers 29 resting scans and the seven ROIs; it states the auditory-task dataset is not in the public release. Task-condition reproduction requires obtaining/preparing those task scans and implementing their channel mapping, event/frame offsets, first-seven-volume handling, task splits, and cross-condition evaluation. Paper reports task zero-shot, task-only, fine-tuned, and joint-trained settings. [M3 runner](../../scripts/reproduce_rest_m3.sbatch); [NeuroBOLT task experiments](https://arxiv.org/html/2410.05341)
- **No FC or uncertainty evaluation.** `utils.get_metrics` currently returns only MSE and Pearson R. The downstream claims around network structure require adding scan-wise signed FC metrics; probabilistic translation would also need calibration/coverage measures rather than R/MSE alone. [utils.py:1007-1059](../../utils.py); [UnEBOLT](https://proceedings.mlr.press/v315/li26g.html)
- **Configuration is partly implicit.** Paper beta settings are absent from the M3 command; primary-vs-sensitivity EEG filtering is hardcoded by train/test mode; there is no config manifest recording code revision, checkpoint hash, ROI, split workbook checksum, preprocessing, and seed. `requirements.txt` leaves several dependencies unpinned. Create a per-run JSON/YAML snapshot for later work.

### First three experiments to run after the current array has finished

Do not modify or cancel the active array or its outputs. Preserve its run label as the existing configuration. Each experiment should use a distinct output directory, fixed split/checkpoint, and the scan-aware postprocessing described above.

1. **Paper-faithful cross-subject rerun (7 jobs, highest priority).** Compare current `full_test` (0.5-Hz high-pass and default AdamW beta) with an explicitly configured primary setting: no extra EEG high-pass, β=(0.9,0.99), 30 epochs, batch 64, same 18/5/6 split and seed. First retain the current results as the filtered/β-default baseline; then change only these preprocessing/optimizer settings together as a reproduction-parity run, and follow with one-factor-at-a-time runs if any differences need attribution. Capture per-held-out-scan R/MSE. Low implementation effort, high value for knowing what result the current model actually reproduces.
2. **Simple regression baseline on the identical splits.** Run per-ROI ridge regression on (a) lagged raw EEG and (b) log band-power/envelope features from each 16-s window, selecting regularization on validation only. Include an intercept/mean-only reference. Report the same per-scan R/MSE, and compute full-scanned-window statistics with identical target preprocessing. This provides an interpretable floor and reveals whether the transformer gains over low-dimensional spectral/neurovascular features; the paper itself compares classic EEG encoders/translation baselines, while the checked-in runner does not. CPU/scikit-learn is likely sufficient, so this is a low GPU-cost experiment.
3. **Joint seven-ROI cross-subject model (1–few jobs).** Extend target loading to all seven values and set `nb_roi=7`; initially retain the same encoder, loss scale convention, optimizer, and split. Compare shared linear multi-output head to seven independent models, then add learned ROI embeddings/query-conditioned decoding only if the simple joint version is stable. Measure per-ROI temporal R/MSE, total fit time, and scan-wise FC similarity/ConnMSE. This is the best research hypothesis from current code plus 2026 UnEBOLT/MARBLE: it tests whether shared learning improves efficiency/functional structure without assuming it beats specialist models. Use validation only for checkpoint/architecture decisions.

**Priority summary:** fix scan-aware evaluation and preflight assertions before interpreting comparative gains; retain the active jobs as useful historical runs; next obtain a paper-parity version; then spend GPU time on multi-ROI/FC modeling. The filter/beta/baseline and logging discrepancies are source-confirmed. Improvements from HRF-aware heads, adaptive scale fusion, Mamba, or newer EEG foundation models remain research hypotheses and need controlled same-split ablations.
